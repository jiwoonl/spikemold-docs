Install SpikePress#

For PC training on an NVIDIA GPU, install CUDA-enabled PyTorch first, then SpikePress. Use the CPU route for a machine without a supported GPU. PYNQ-Z2 runs an exported package in a separate ARM environment.

1. Create the workstation environment#

The commands below use Linux x86-64, Python 3.11, and a POSIX shell. SpikePress requires Python 3.10 or later. Install a C compiler and the development headers for your Python version to build the native extensions.

git clone https://github.com/jiwoonl/SpikeMold.git
cd SpikeMold
python3.11 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip

Activate .venv in each new terminal. Run the examples from the repository root.

2. Install PyTorch for your device#

NVIDIA GPU (recommended for training)#

Run nvidia-smi to confirm that the driver sees your GPU. In the PyTorch installation selector, choose your OS, Pip, Python, and a CUDA build supported by your NVIDIA driver. Run the generated command inside .venv.

For example, the training guide was checked with PyTorch 2.10.0 and CUDA 13.0 on an RTX 3080. Use this example command if your driver supports CUDA 13.0:

python -m pip install 'torch==2.10.0' --index-url https://download.pytorch.org/whl/cu130

The prebuilt wheel supplies the CUDA runtime libraries it needs. Install a compatible NVIDIA driver. Install the CUDA Toolkit separately if you build CUDA code from source.

CPU-only workstation#

On Linux x86-64, install the CPU wheel:

python -m pip install 'torch==2.10.0' --index-url https://download.pytorch.org/whl/cpu

For another OS or GPU backend, use the PyTorch selector to find the appropriate wheel. The examples in the GPU training guide were checked on NVIDIA CUDA.

3. Install and verify SpikePress#

python -m pip install -e '.[compiler]'
python -m spikepress.cli doctor --require compile

For the CUDA route, verify that PyTorch can allocate and execute on the GPU:

python - <<'PY'
import torch

print("PyTorch:", torch.__version__, "| CUDA build:", torch.version.cuda)
if not torch.cuda.is_available():
    raise SystemExit("CUDA unavailable. Check the selected wheel, NVIDIA driver, and GPU visibility.")
print("GPU:", torch.cuda.get_device_name(0))
assert (torch.ones(1, device="cuda") + 1).item() == 2
PY

If the CUDA build prints None, check which wheel is installed in this environment. If it prints a CUDA version but no device is available, check nvidia-smi, driver compatibility, and settings such as CUDA_VISIBLE_DEVICES. See train on a GPU for model and batch placement. Compilation and the integer golden example below use CPU tensors in the same environment.

Check the native examples#

python -c 'from spikepress.backends.pynq import _native_runtime, _native_mmio; print("native imports OK")'
python tools/check_bitstream_bundle.py
python examples/compile_model.py --output runs/first-compile
python -m spikepress.cli inspect runs/first-compile/model.spm

Choose a new output directory. The compile example prints PASS_CPU_GOLDEN and hardware: NOT_CHECKED. The image check reads files without opening a board. If native imports fail, check that a C compiler and the headers matching your Python are installed, then reinstall the package. Native extensions are optional at installation, but application encoding and C host execution need them. See runnable examples for further checks.

Board inference#

The board needs a compatible PYNQ-Z2 BSP/OS with PYNQ, Python 3.10+, NumPy, a C compiler and matching Python headers. Build the native extensions on ARM and ensure the board account has the device permissions required for MMIO and DMA. Installing this Python package does not create a PYNQ BSP or configure a board. PyTorch is not required to run an exported package.

The matching .bit, .hwh and .profile.json are in bitstreams/pynq-z2/ and arrive with an ordinary clone or pull. Follow the board walkthrough to install on the board, export and transfer an input, program the PYNQ-Z2 overlay, and compare the output. Programming and board operation require the applicable authorization. The runtime defaults to program=False; only omit programming when the matching overlay is already loaded.

For an admitted resident or Count model, board.prepare_input(inputs) creates an owned snapshot for repeated calls. Each call still executes; reload, close or fault invalidates the handle. Other virtual and hybrid programs do not support it. See compatibility for the image and measurement limits, and runtime recovery for faults.
