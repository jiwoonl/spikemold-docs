Troubleshooting#

Start with the failing stage and retain the complete error, input shape/dtype, target, package identity and software version. spikepress doctor checks imports without accessing a board; it does not prove device readiness.

Symptom

Meaning and next action

doctor --require compile fails

Install a suitable PyTorch build and the compiler extra in the same Python environment. See installation.

A required native symbol/module is missing

Rebuild with a C compiler and Python headers for the actual runtime environment. C-required operations reject instead of silently running a Python numerical fallback.

Preflight suggests pruning or tiling

This is a candidate, not an applied transform or proof of fit. Inspect the exact compiler result; retrain and validate when model semantics change.

Compiler: NOT_RUN

Preparation skipped validation. Run compile on the deployment model/example.

Compiler rejects a node, geometry, decay or capacity

Follow the report’s code/node/hint and the support matrix. Do not change the meaning of an unsupported model implicitly.

A 4D input is ambiguous

Supply explicit B,T,C,H,W for 2D or B,T,C,L for 1D. Transpose channels-last data explicitly before adding B.

save refuses an existing file

Use a new .spm path. Training/export does not update an old artifact in place.

A prepared input is rejected after reload

The handle belongs to its original Board/load. Prepare a new handle for the new model.

Measurement-enabled connection is rejected

Use the exact admitted image/profile and explicit inference-only policy; see compatibility. Do not disable profile checks.

Latency differs between ordinary and prepared runs

Prepared timing excludes first packing/seal. Retain clock, wait policy, input, head, warmups, samples and CPU time when comparing.

J/input or J/spike is unknown

Supply compatible activity and measured calibration evidence. Missing energy is not zero energy. See cost estimation.

Timeouts and faults#

A transfer timeout, malformed/faulted terminal or partial publication can leave device ownership uncertain. The runtime can latch a fault and quarantine buffers and transport objects. Closing, reloading or dropping the Python object does not establish DMA drain.

Preserve diagnostics and allocations and follow the target-specific recovery contract. Do not clear a software fault flag, free quarantined buffers or add an automatic retry as a workaround. A separately qualified drain/reset procedure is required for uncertain ownership.

Reporting a reproducible problem#

Include the smallest model and input that show the problem, the full error, Python/PyTorch/native versions, target and source revision. For hardware issues, include bit/HWH/profile/package identities and the existing receipt. Remove credentials and private data. State whether the failure occurred on CPU, simulation or actual hardware. Use the repository’s issue tracker.
