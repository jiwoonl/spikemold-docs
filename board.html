Deploy on PYNQ-Z2#

Export a small model on your development machine, then run one input on the board. This walkthrough programs the included overlay on its first board run; it does not run as part of CPU tests.

Prerequisites#

  • A PYNQ-Z2 running a compatible PYNQ BSP/OS with PYNQ and Python 3.10+. NumPy, a C compiler and Python headers matching the board interpreter are needed to build the native ARM extensions. pip install does not create a PYNQ BSP. Do not copy x86 extensions to the board.

  • Board-account permissions for the required MMIO and DMA devices, and the applicable authority and procedure to operate and program the board.

  • The same SpikeMold Git revision on workstation and board. Its bitstreams/pynq-z2/ directory contains the .bit, .hwh and .profile.json files; no Git LFS or separate image download is required.

If the board does not yet boot PYNQ, follow the upstream PYNQ-Z2 setup guide and board image downloads first. The Git bundle contains the accelerator overlay, not an operating-system image. Existing physical results used Linux ARMv7, Python 3.10.4 and NumPy 1.21.5; a different board software image must pass the checks below. Use the board exclusively when programming or running it.

1. Export on the workstation#

From the repository root with the development environment active:

python tools/check_bitstream_bundle.py
python examples/compile_model.py --bitstream bitstreams/pynq-z2/spikemold.bit \
  --output runs/board-model
python -m spikepress.cli inspect runs/board-model/model.spm
git rev-parse HEAD

Use a new output directory. Expect PASS_CPU_GOLDEN, compiler_accepted: true and a nonempty golden. This reads the image metadata without opening a board. Record the commit and retain the matching image trio with the model.

2. Transfer the model and input#

Set your board login and hostname. Transfer the files to a directory under that account’s home directory:

export BOARD_HOST=your-board-user@your-board-hostname
ssh "$BOARD_HOST" 'mkdir -p spikepress-demo'
scp runs/board-model/model.spm runs/board-model/events.npy runs/board-model/golden.npy \
  "$BOARD_HOST:spikepress-demo/"

Clone or pull the same commit on the board to obtain the image, SDK source and helper. If the board has no network, copy that checkout and its image trio unchanged. Compare hashes of the transferred model, input and golden with the workstation copies.

3. Install on the board#

From the matching checkout on the board, select its compatible PYNQ interpreter. The path below is an example; check your board’s actual interpreter:

git clone https://github.com/jiwoonl/SpikeMold.git
cd SpikeMold
# Check out the same commit recorded during export if needed.
export BOARD_PY=/usr/local/share/pynq-venv/bin/python3
"$BOARD_PY" --version
"$BOARD_PY" -m pip install .
"$BOARD_PY" -m spikepress.cli doctor --require runtime
"$BOARD_PY" -c 'from spikepress.backends.pynq import _native_runtime, _native_mmio; print("native imports OK")'
"$BOARD_PY" tools/check_bitstream_bundle.py

Optional: "$BOARD_PY" -m spikepress.selftest checks native packing, decoding and in-memory MMIO operations without FPGA access. These checks do not prove physical MMIO, DMA or board execution.

4. Program and compare one output#

From the board checkout, point to the transferred files and use a new output path:

BOARD_DEMO="$HOME/spikepress-demo"
"$BOARD_PY" examples/run_board.py \
  --bitstream bitstreams/pynq-z2/spikemold.bit \
  --model "$BOARD_DEMO/model.spm" \
  --inputs "$BOARD_DEMO/events.npy" \
  --golden "$BOARD_DEMO/golden.npy" \
  --output "$BOARD_DEMO/result.json" --program

On a compatible working board, expect PASS_BOARD_GOLDEN and golden_compared: true. The helper compares the full T,H,W,C output through the native dense decoder. --golden is limited to the bounded resident v12 binary-event path; it is not a generic Count, virtual or hybrid validator.

--program explicitly loads the included overlay. The helper and runtime otherwise default to program=False: omit the flag only when the matching overlay is already loaded. The helper requests unmeasured_inference=True for the included image. A verified file alone does not attest the loaded image.

5. Reuse an input#

After the first run has loaded the matching overlay, repeat with a new output and --prepared:

"$BOARD_PY" examples/run_board.py \
  --bitstream bitstreams/pynq-z2/spikemold.bit \
  --model "$BOARD_DEMO/model.spm" \
  --inputs "$BOARD_DEMO/events.npy" \
  --golden "$BOARD_DEMO/golden.npy" --prepared \
  --output "$BOARD_DEMO/prepared-result.json"

For repeated calls in one session:

from pathlib import Path

import numpy as np
import spikepress

demo = Path.home() / "spikepress-demo"
inputs = np.load(demo / "events.npy", allow_pickle=False)
with spikepress.connect(bitstream="bitstreams/pynq-z2/spikemold.bit", unmeasured_inference=True) as board:
    board.load(demo / "model.spm")
    handle = board.prepare_input(inputs)
    first = board.run(handle)
    second = board.run(handle)

The handle is a snapshot owned by that Board and model load. Every call transfers and executes again; reload, close or fault invalidates it. The path supports admitted resident and Count models, not all virtual or hybrid models. Prepared timing excludes the initial encoding and seal.

Results and recovery#

A golden match checks this model and input. The included image’s observer has measurement_valid=false; the helper does not measure energy, PL-only latency or full-dataset accuracy. See measured results for their scope. After a timeout or fault, do not retry, reload or program as a recovery shortcut: uncertain DMA ownership may be quarantined. Follow runtime recovery.

The historical release-bundle procedure requires its original bundle and has different workloads. See the release gates for final qualification.
