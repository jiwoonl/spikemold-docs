Supported operations#

Support depends on the operator, input layout, numeric meaning and selected execution path. The tables below describe the included PYNQ-Z2 image and the explicit host backend. preflight reports early risks; compile decides exact acceptance for your model and example. Neither replaces board load-time checks.

Native event layers#

Use spikepress.nn for hardware-aligned training and export. Parameters have floating-point training shadows; deployment uses signed INT4 weights and INT16 state with the defined reset/decay and accumulation order.

Layer constructors and parameters document signatures and defaults. MaxPool2d and Threshold retain the existing EventMaxPool2d and EventIF implementations. Native temporal state carries within one call and resets between calls. Exact admitted retention values are 1, 1/2, 1/4, 1/8 and 1/16. General continuous PLIF, subtractive-reset or external-library neuron semantics are not silently converted.

Explicit C host operations#

Select allow_host_ops=True to capture supported fixed-shape host operations. The default follows source float32/float64 precision. Mixed precision, layouts, mutation and transitions back into binary event input have explicit checks.

Where operations run#

Resident OR is disabled in the included image; its legacy API is documented only for compatibility. ADD uses the explicit residual path.

The native table describes event-engine execution; the host table describes explicit C execution. A hybrid graph can contain both, subject to supported boundaries. Bounded residual addition can use host-composed programs, while resident residuals and weighted FPGA readout are disabled in the included image. The compiler does not provide a general fallback for unsupported operators.

LSTM/GRU, arbitrary attention/dynamic graphs, general NIR imports and arbitrary SpikingJelly/snnTorch checkpoints are outside the verified general deployment scope. An operation available in PyTorch training is not automatically supported by the compiler. Follow PyTorch authoring before porting a model.

Shape, precision and capacity#

T is 1–64 for admitted event paths. State, row geometry, index/weight tables, resident layers, tiling and output bounds all constrain fit. Parameter count alone is insufficient. Preflight reports known rejections, unknown inspection coverage and possible optimizations; suggestions are never applied silently. A compiler acceptance applies to the supplied example and target. Read hardware-scale guidance for memory interpretation.

Installation and validation scope#

Python 3.10+ and PyTorch are needed for authoring/compiler work. NumPy-only execution of an exported package is supported on a compatible board SDK. Application encoding and C host execution require the matching native extension. Installed-wheel CI covers Python 3.10/3.12 CPU combinations for its selected examples; it does not certify every OS, PyTorch version or hardware setup.

Performance records measured model/input scopes. CPU, mock, simulation, route and physical board evidence are distinct. The included image uses functional inference with an invalid hardware observer; electrical energy and full-dataset FPGA accuracy retain separate qualification requirements. See compatibility, runtime recovery, application bundles and release gates.
