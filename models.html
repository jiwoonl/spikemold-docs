Model recipes#

examples/model_recipes.py provides bias-free DVS SCNN, depthwise MobileNet, feedforward speech CNN, and OR residual training examples. They are small native SpikePress designs, not reproductions of published architectures or accuracy. Use HybridClassifier for a host Linear head: its input is the mean spike rate over time and space, matching spikepress.readout.linear.

--recipe vgg --stem-stride 1 adds a CIFAR-10 VGG-family candidate with eight dense K3 convolutions, repeats 1/1/2/2/2, and five binary max pools. Its default five widths are 64/64/64/64/64, selected for the current physical CSR banks. It reuses the two-stage trainer, CIFAR encoding, native shift-LIF and explicit PS classifier. It is an adapted VGG convolution topology without BN/bias, not a published-model accuracy reproduction. The frozen performance run and accuracy-gated terminal QAT are in the CIFAR VGG plan. Passing compilation does not establish its task accuracy.

The eight-block or_resnet recipe is trainable but exceeds the current target’s one-residual-merge contract and is rejected by compilation. OrBackbone(preset, blocks=1) is the separately qualified deployment smoke. Do not train the larger recipe expecting its whole graph to deploy on the current bitstream.

Depthwise K3/P1 at S1 or S2 is qualified for C64, C128, C256, C512 and C1024. The wider cases require exact depthwise connectivity: input channels, output channels and groups must be equal. Other grouped shapes retain their previous restrictions. C1024 passed production control-v12 XSim at T=1 and T=64 for both strides, including the last OC8 group. Normal state, row, CSR and image capacity checks still apply; this is not permission for arbitrary spatial sizes or grouping.

Compilation of a recipe smoke and integer-golden equality do not establish trained task accuracy. A terminal host classifier requires a separate backbone artifact and caller-owned head weights. Include the host head in end-to-end latency and energy measurements.

Learnable decay uses LIFConv2d(..., decay="learnable") (also Linear/Conv1d). The training forward uses the hardware shift codebook with a straight-through gradient. spikepress.prepare() freezes the trained code to an exact shift on a copy; the source training model remains learnable. This adds no RTL decay path.

Training and exporting#

Start with the prepared-data contract and bounded CPU pilot. The commands below describe larger two-stage training runs, default to CUDA and require existing datasets; they are not quick-start commands.

examples/train_recipes.py uses the existing examples/train/utils.py two-stage engine through native model/dataset adapters. The engine selects the strict best validation-loss checkpoint, restores it before QAT, and starts a fresh AdamW optimizer. Each stage has its own learning rate, minimum/maximum epoch counts and early stopping patience. Native layers use float weight/state diagnostics in FP32 and the deployment INT4/INT16 grid in QAT; both use the same projected shift-codebook decay. These modes are recorded separately.

Before training, three calibration passes use eight deterministic train-prefix samples without labels. Per-output positive pre-firing accumulator values set a 90th-percentile threshold, followed by gain 2. The first layer starts at learnable codebook shift 2. Calibration and learnable decay add no RTL. Compilation checks the backbone before and after training. The classifier is explicitly host-only, not a biased neural layer in the FPGA graph.

conda activate fpga
PYTHONPATH=src python examples/train_recipes.py --recipe mobilenet \
  --data /path/to/prepared/cifar --output /path/to/new/run \
  --widths 16,32,64,128 --timesteps 8 \
  --fp32-epochs 60 --qat-epochs 20 --min-epochs 10 --patience 8
PYTHONPATH=src python examples/train_recipes.py --recipe dvs_scnn \
  --data /path/to/prepared/dvs --output /path/to/new/run \
  --widths 16,32,64 --stem-stride 1 --timesteps 16
PYTHONPATH=src python examples/train_recipes.py --recipe speech_cnn \
  --data /path/to/prepared/shd --output /path/to/new/run --timesteps 64

The output includes FP32/QAT best checkpoints, backbone.spm, checkpoint.pt, host_head.npz, protocol/history and a first fixed validation sample with input.npy, golden.npy and host_logits.npy. FP32-best, QAT-start and QAT-best validation metrics distinguish architecture/training from quantization loss. QAT export must match the compiler integer golden; a failure leaves a receipt and rejects the candidate. Export does not establish board execution.

DVS uses prepared binary [N,16,2,128,128] recordings. T below 16 OR-bins non-overlapping intervals. T above 16 is rejected because these prepared frames cannot recover finer temporal resolution. CIFAR uses uint8 [N,3,32,32], T-dependent deterministic level/phase coding and the existing training-only augmentation. NPZ files contain x, y and unique disjoint split ids. The native trainer transfers raw uint8 image batches to the training device and performs level/phase encoding there in one tensor operation. This avoids sample-by-sample CPU encoding and transferring T expanded float frames. The existing seeded CPU augmentation is unchanged. Calibration and compilation still receive the same encoded tensors; CPU training uses the same batch encoder. Convolution already combines batch and timestep dimensions. Membrane, spike and reset recurrence remains sequential over time to preserve neuron semantics. --compile-multistep optionally fuses that CUDA recurrence with torch.compile. It preserves the timestep dependency; it does not treat timesteps as independent samples. INT4 updates use fusion only when the existing absolute bound proves that signed-16 saturation cannot occur. All other updates retain the canonical event-order saturation path. CPU compile/export and default training remain eager. Compilation has a startup cost and requires a working PyTorch CUDA compiler. Metrics accumulate on the training device and transfer once per epoch; finite loss and gradient guards remain active before optimizer updates. Speech uses train_x.npy/validation_x.npy and matching *_meta.npz with labels and ids. The input is [N,1500,88] little-bitorder packed SHD data; 700 auditory units become one Conv1D spatial axis. OR time binning supports T=1..64; changing T changes preprocessing and must be reported. Prepared SHD subsets are not full-dataset benchmarks.

Omitting --train-samples/--val-samples uses the whole prepared split. Limits select fixed prefixes. Official test sets stay unopened. Historical one-stage results remain reproducible with --legacy-pilot --epochs 10.

To continue an interrupted two-stage run, use --resume-from /path/to/parent with a new --output directory and the same model, data, seed, batch sizes and stage schedule. The trainer restores the epoch-boundary model and AdamW state, replays early-stopping history, and preserves best checkpoints. The parent is never overwritten. resume.json binds parent hashes and the current source; older checkpoints without RNG state are labelled accordingly. New checkpoints also save Python, NumPy and PyTorch RNG state. Runtime optimization choices are recorded separately from the model protocol.

--head-mode mean, count, temporal or flatten selects a host reduction. Temporal weights are a normalized learned per-timestep vector. --work-coefficient and --tap-coefficient enable the existing OC8-work and protected-output regularizer; both default to zero. Set --work-ceiling explicitly for an ablation. Its work counts are a compiler-aligned activity proxy, not measured energy. Normalize task accuracy first before choosing an efficiency penalty.

The flatten head retains spatial positions after averaging time; it runs on the host, with a larger classifier/transfer cost than global pooling. Use --fp32-only to save selected float checkpoints without QAT or integer export. --lr-schedule cosine enables cosine LR decay with resumable scheduler state. See training accuracy for reference comparisons and the one-time terminal QAT workflow.

Compile-only capacity screening is available before an expensive campaign:

PYTHONPATH=src python examples/sweep_recipes.py --output new-capacity-report.json

This checks widths, T and DVS stem stride. Rejected candidates retain their compiler reason; no synthetic accuracy, cycles or energy are added to the report. Runtime capacity checks still apply after training changes sparsity.

Verify a saved two-stage export offline, then manually qualify the same bound assets when the board is available:

PYTHONPATH=src python examples/qualify_model.py /path/to/run
python examples/qualify_model.py /path/to/run \
  --bitstream /path/to/spikemold.bit --program --windows 10 --wait-policy auto

The board command validates all saved asset hashes, compares FPGA terminal spikes and host classifier logits, and reports call latency. It never treats the offline check as FPGA proof and does not supply an energy measurement. --program is an explicit request to write the image. Historical one-stage runs retain train_recipes.py --verify-existing and their separate validation-proof/ receipt.

For a small supported residual model, examples/train_features.py --feature residual exports a three-convolution, one-OR-merge model. This is residual feature coverage, not deployed ResNet19. Multiple residual reuse and pre-spike ADD remain unsupported.
