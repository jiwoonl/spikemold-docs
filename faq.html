Common questions#

Can I use my existing SpikingJelly or snnTorch model?#

Keep its architecture, discretization, reset, decay, quantization, input encoding and readout meaning explicit. SpikePress preserves the usual PyTorch authoring experience, but prepare is not an arbitrary checkpoint importer. Start with PyTorch authoring and preflight. Matching weight shapes alone does not establish numerical equivalence.

Is every supported operator executed in PL?#

No. The selected image exposes a bounded event engine. Explicit C host islands and host classifiers form hybrid inference and have different costs. The compiler rejects an unsupported connection instead of changing its meaning. See supported workflows.

Can the compiler make any oversized network fit?#

Tiling and segmentation can address specific state/lifetime constraints while adding transfers and STARTs. They cannot remove every physical bound. Preflight shows candidates; compilation and load-time admission decide the actual case. For example, Gesture LIF32 requires at least eight tiles against the qualified maximum of four and remains rejected. Pruning, changing widths/T or substituting operators requires explicit model and accuracy validation.

Is a multi-step SNN just a larger convolution batch?#

Convolution can combine B and T, while the neuron recurrence depends on prior membrane state and reset. Independent timestep calls reset native authoring state and can change predictions. Native CPU and optional CUDA compiled recurrence have different limits. Read training and execution, then measure after warmup on the intended device.

Why do I still see float64?#

Native event PL arithmetic uses INT4 weights and INT16 state. C host plans follow source float32/float64 precision by default; dynamic INT8 is explicit. Some diagnostic dense-output and application classifier interfaces retain float64 buffers/weights under their existing contracts. This does not change PL arithmetic. Use the execution guide to select and verify a lighter supported host path rather than assuming every API uses one dtype.

Can I install the package and immediately run on a board?#

Compiler-only CPU use needs no board. Actual deployment additionally needs a compatible PYNQ/ARM environment, native extension and qualified bitstream/HWH/ profile bundle. The verified image trio is tracked in bitstreams/pynq-z2/ and arrives with ordinary clone/pull; no separate image release download or Git LFS is needed. Follow installation and the board walkthrough. The board does not need PyTorch for an already exported package.

Does prepare_input cache a prediction?#

It caches an owned validated input snapshot for a particular Board/model load. Each run transfers and executes freshly; Count intermediates are recomputed. The optimization is available only for its admitted resident/Count paths. Reload, close or fault invalidates use. Retain a strong handle reference.

Does PASS_CPU_GOLDEN mean my model runs on the FPGA?#

It means the checked CPU model/input agrees with the integer golden and the package round-trip passed. It does not establish device correctness, latency, energy or task accuracy. Use the matching board procedure for physical proof and retain independent full-dataset accuracy and measurement evidence.

Why is energy unknown despite a successful inference?#

Memory and traffic estimates are not electrical measurements. J/input and J/input-spike require compatible measured calibration with declared window, denominator and image/model identity. PYNQ-Z2 functional inference reports measurement_valid=false. See cost estimation and measurement scope.

Can I retry after a timeout?#

An uncertain transfer can leave DMA ownership unresolved. A fault latch or quarantine is not cleared safely by deleting objects, calling close, or reloading. Preserve allocations/diagnostics and follow the target-specific recovery contract.
