Prepare data for recipe training#

The repository does not download or convert a dataset for train_recipes.py. Prepare splits independently and retain the dataset license, preprocessing, class mapping and source identities. Start with the synthetic training example if you do not have prepared data. Use a source checkout with the compiler extra; these scripts are not bundled as a wheel workspace.

CIFAR and DVS split files#

For --recipe mobilenet and --recipe dvs_scnn, place train.npz and validation.npz in the directory passed to --data. Each archive must contain x, y, and ids, with equal nonzero first dimension N; y and ids are one-dimensional. x is uint8 or bool, y is integer, and IDs must be unique within each split and disjoint across splits. Use NumPy Unicode strings or integers for IDs: loading uses allow_pickle=False, and the pilot serializes the IDs to JSON. Object and byte-string IDs are not suitable for this workflow.

For raw CIFAR, the loader encodes pixels into spikes and applies deterministic train-only crop/flip augmentation; validation is not augmented. Temporal arrays must be binary. Keep the real validation split independent of training; fixed prefix limits do not create a valid split and are only smoke-test subsets.

Packed speech files#

For --recipe speech_cnn, provide train_x.npy, validation_x.npy, train_meta.npz, and validation_meta.npz. Each input is uint8 [N,time,88] with 700 little-bitorder packed channels; the four padding bits must be zero. Metadata contains one-dimensional ids and integer labels in 0–19. Counts must match and IDs must be unique and disjoint across splits. The legacy pilot uses T=16 and therefore needs at least 16 input time bins; it OR-bins nonempty intervals. The commonly prepared SHD form has 1500 bins. No raw audio or event conversion is performed here.

Run a bounded pilot#

After providing compatible data, this opt-in CPU command uses only a prefix of each already separate split and one epoch. Choose a new output directory:

python examples/train_recipes.py --recipe mobilenet --data /path/to/prepared-cifar \
  --output /tmp/spikepress-recipe-pilot-new --device cpu --legacy-pilot \
  --epochs 1 --batch-size 2 --train-samples 4 --val-samples 2

Replace the data path with your files. The example is a workflow smoke, not an accuracy result; compilation can reject the actual model/shape. On success, protocol.json binds source and split hashes, history.json contains validation metrics, and checkpoint.pt, backbone.spm, host_head.npz, probe.npy, probe_golden.npy, and result.json describe the candidate. The exact golden check covers the fixed probe, not the full validation set or a board. The classifier is a host head. Never use the official test set as validation.

Without --legacy-pilot, the two-stage trainer uses FP32 and QAT schedules; --epochs is accepted only with --legacy-pilot. The default device is CUDA and default stage limits are much larger. Check python examples/train_recipes.py --help and model recipes before starting a real training run. Record all changes to data, timesteps and splits.

Export profile after a legacy pilot#

The legacy recipe launcher does not accept --bitstream; its package uses its existing compiler contract. Do not assume that artifact is admitted by the selected production image. For actual deployment, reconstruct the exact saved native backbone/configuration, bind the real image via prepare/compile’s bitstream= argument and retain the trained host head and preprocessing. See compatibility. This is a model-specific re-export, not automatic conversion of an arbitrary checkpoint.
