Memory, traffic, latency and energy estimates#

Cost reports have three distinct evidence levels: static bounds, simulation for specified inputs, and measurements from a bound board/model configuration. A model’s parameter count alone cannot predict its FPGA latency or energy.

Try inspection on CPU#

python examples/compile_model.py --output /tmp/spikepress-cost-new
spikepress inspect /tmp/spikepress-cost-new/model.spm
python -m json.tool /tmp/spikepress-cost-new/preflight.json

This synthetic example produces an accepted package and host golden for one input. The inspection is a static report; it does not measure latency, total traffic or energy. The .spm and events.npy are saved in that directory. Use a fresh output path for each run. To select a qualified image’s compiler profile, append --bitstream bitstreams/pynq-z2/spikemold.bit with matching HWH and sidecar available on the workstation.

Before training: memory pressure#

report = spikepress.preflight(model, example, target="pynq-z2")
print(spikepress.format_preflight(report))

Each inspected layer exposes full_state_bytes for an untiled window and dense_weight_payload_upper_bound_bytes when the target uses INT16 state and INT4 weights. These use the existing target dtype and OC8 layout:

  • State bytes = output spatial positions × padded OC8 groups × 8 × 2.

  • Dense weight payload upper bound = rows × padded OC8 groups × 8 / 2.

State persists over T; its storage is not multiplied by T. These figures are per-layer logical storage. They omit index tables, temporal metadata, physical BRAM padding, residual lifetimes, DMA arenas and host buffers. Summing them does not give peak deployed memory or training GPU memory. Tiling changes peak resident storage and traffic; actual quantized sparsity can reduce weight payload. Training memory additionally depends on saved autograd tensors, optimizer state, dtype and batch size and must be profiled on the chosen device.

Specialized legacy parameter exporters have their own cost reports and fixed model geometry. Their array sizes do not describe a general compiled model; see the developer legacy exporter reference.

spikepress inspect model.spm displays the validated artifact hash, input contract, encoded execution plan, image boundaries and available memory allocation bounds. It does not measure traffic, latency or energy, or verify the attached board.

After compile: input-dependent simulation#

Use the existing compiler result for the selected backend:

  • SparseEventCompileResult.simulate_communication(events) provides static communication bounds and stage-simulated traffic. The counts use 32-bit words; multiply a specific category by 4 for bytes. Input, model-image, stage-cut write/read and result categories have different meanings; do not add overlapping totals.

  • Temporal results such as the training-workflow example support compile_input(events), returning the encoded input row_stream and a CPU golden result. Its stream_words.nbytes is the encoded input size only, not total DDR traffic. This is not a full hardware schedule simulation.

  • TargetSpec.estimate(graph, activity, cycle_coefficients=...) reuses the temporal cost model. Cycles require compatible graph, target, timing mode, workload range and held-out error evidence. Missing or incompatible calibration is unknown. This estimator’s accepted graph/contract is not interchangeable with every public compiled package.

Keep the package/source/input hashes with each result. A logical graph’s spike count and a hypothetical cut length do not prove actual DMA traffic, physical BRAM accesses or board speed. The current framework has scoped estimators; it does not yet expose a calibrated universal FPGA simulator.

Measured J/input and J/input-spike#

The existing model-bound measurement tools verify raw captures and their manifests:

spikepress measure-report --package QUALIFIED_PACKAGE_DIR \
  --runs CAPTURE_SESSION_1 CAPTURE_SESSION_2 --output new-measurement.json
spikepress fit-energy --package QUALIFIED_PACKAGE_DIR \
  --training CAPTURE_SESSION_1 --validation CAPTURE_SESSION_2 \
  --output new-energy-model.json

These commands analyze existing data; they do not operate a board. A generic .spm file is not a qualified measurement directory. Fit requires separate new-input development sessions with 216 windows, subject holdout and matching image/model bindings. Output paths must be new. Keep fit diagnostics including held-out error and the constant-mean baseline; accepting a fit is not evidence that it is useful.

Quantity

Definition

Whole-board compute J/input

Sum of compute-window energy / inference windows

Whole-board end-to-end J/input

Batch measurement energy / inference windows

Compute J/input-spike

Sum of compute-window energy / sum of input spikes

End-to-end J/input-spike

Batch measurement energy / sum of input spikes

One input means one inference window, not one timestep or one batch. Input spikes and internal/output spikes are distinct denominators. Use a ratio of sums across a dataset, not the mean of per-input ratios. Zero total spikes produce None; the baseline energy may still be positive. Whole-board energy divided by spikes is not the intrinsic energy of a single spike or memory access.

Estimate a compatible input from a fitted model#

import json
from spikepress.energy import predict_energy

calibration = json.load(open("qualified-energy-model.json"))
prediction = predict_energy(
    calibration,
    binding=verified_run_binding,  # Independently verified current bit/model/evidence.
    effective_ac=logical_trace["effective_ac"],
    input_spikes=logical_trace["input_spikes"],
)
print(prediction)

Use activity from the same input trace. Do not copy calibration["binding"] into a different model’s request to bypass compatibility. The existing predictor is experimental and applies only to the same calibrated reference model and calibrated activity range. It exposes board_compute_j_per_input and board_compute_j_per_input_spike, while retaining energy_j. Missing/zero spike count leaves the spike-normalized field None. An incompatible model, invalid calibration or activity outside the fitted range returns UNKNOWN_* with null energy. Static preflight always labels energy and latency unknown. Synthetic coefficients test units and rejection behavior; they do not establish measured energy or a validated speed prediction.

Gates for broader simulation#

  1. Bind compiler/package, input activity, exact RTL/bitstream, clock and host transfer policy. Retain the measured hardware traffic/cycle evidence, selected model and representative input activity together with the compiler/runtime revision.

  2. Validate memory lifetime/arena sizes and simulated event/traffic counts on the same input bytes. STOP if a package route lacks that evidence.

  3. Fit compute, end-to-end and idle energy separately from qualified existing sessions. Report validation error and comparison against a simple constant baseline. STOP on poor fit, incompatible binding or extrapolation.

  4. Show estimate, units, denominator, calibration reference and uncertainty together. Keep unknown fields visible. Cross-model estimates require held-out model validation; new boards/clock/memory policies require new qualification. Do not use unqualified coefficients for automatic latency or energy optimization.

The current compiler optimization plan is in HW-scale workflow.
