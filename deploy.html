Deploy an event application#

An application binds an existing validated .spm, event preprocessing, a host head, and ordered class labels. It reuses the compiler, artifact validator, Board and C result kernels. It does not change a model, choose a hardware ABI, quantize a head or establish accuracy. The default mean head uses spikepress.application.v1; explicit count, temporal and flatten heads use v2.

Run a complete CPU export#

After installation, including the native C extension:

python examples/application_deployment.py --output runs/first-app
python -m spikepress.cli inspect-deployment runs/first-app/application

This writes raw_events.npy, encoded.npy, model.spm, application/ and report.json; the report retains hardware_qualification: NOT_CHECKED. The two illustrative labels are active and inactive. The head is fixed for the example and has no trained accuracy claim. Add --bitstream with the qualified local image trio when exporting for deployment.

Bind your own application#

The API fragment below assumes model.spm, class-by-channel weight, class-sized bias and ordered class_names from your own trained head.

import spikepress

spikepress.export_deployment("model.spm", "new-application",
    head_weight=weight, head_bias=bias, labels=class_names,
    preprocessing={"encoding": "uniform_binary_or", "window_start": 0,
                   "window_end": 16000, "timesteps": 16,
                   "shape_hwc": [64, 64, 8]})
app = spikepress.Deployment("new-application")
print(app.report())

The input contract is explicit [time,y,x,channel], with timestamps in the caller’s declared unit and a half-open [start,end) window. The C kernel bins uniformly into binary [1,T,C,H,W]; coincident events use OR. It rejects out-of-window events, noninteger coordinates and nonfinite values instead of dropping them. This encoding must match training. It does not implement an implicit sensor fold, crop, polarity reorder or normalization. Declare and validate those transforms upstream if the trained model needs them.

The default head uses mean over time and space, then float64 linear weights and bias on the host. Other explicit reductions are:

  • reduction="count": sum over time and average over space per channel.

  • reduction="temporal", temporal_weights=[...]: weighted timestep sum and spatial mean; weights must be nonnegative and sum to one within 1e-5.

  • reduction="flatten", time_bins=N, grid=[H, W]: adaptive time and spatial bins, flattened in time-bin, channel, row, column order. Weight width must be N * channels * H * W.

For example, pass reduction="flatten", time_bins=2, grid=[2, 2] to export_deployment along with a head of the corresponding width. These modes use the existing native result-frame feature and linear kernels. Reduction metadata is fixed in the manifest; changing it requires a new export and matching head. Existing v1 mean assets keep their original interpretation. Application export accepts v12 binary event packages with terminal spike records. Resident and segmented programs retain their compiler capacity limits.

python examples/application_deployment.py --output /tmp/new-spikepress-app
spikepress inspect-deployment /tmp/new-spikepress-app/application

Use a new output directory. The example creates model.spm, an application/ manifest and assets, raw_events.npy, encoded.npy, and report.json. For a locally available, qualified image and matching sidecars, add --bitstream bitstreams/pynq-z2/spikemold.bit when exporting; this selects its compiler profile without programming hardware. Transfer the complete application and matching image bundle to the board through your established procedure.

This example encodes and exports on the CPU; its report says hardware qualification NOT_CHECKED. It needs the installed C native extension. Compiler-only installs can export/inspect applications but execution raises if native code is missing. No Python numerical fallback is selected.

When a matching profile is qualified and board execution has been authorized, use the existing Board lifecycle:

# board is an explicitly authorized, connected, matching Board session.
app.load(board)  # Explicit load; does not retry or clear a fault.
prediction = app.run(board, raw_events, window_tag=17)
print(prediction["label"], prediction["logits"])

run requires the same explicitly loaded application snapshot. It encodes in C and passes the existing Classifier to native Board.run(readout=...). Reloading another model invalidates that application binding. Existing board fault/quarantine rules still apply. The wrapper’s NOT_CHECKED field is a qualification label, even when a real device is used; it is not a test receipt. Python still orchestrates Board/DMA calls in the current runtime: see the C migration gates before calling the whole driver C.

For repeated use of the same input with a supported resident model or Count program, board.prepare_input(input_tensor) creates an owned snapshot. Pass the handle to board.run(); every call still transfers the input and executes the model. Reloading or closing the Board invalidates it, and other virtual and hybrid programs do not support this handle. Include the one-time preparation cost when reporting end-to-end timing. See installation for an example and the full lifecycle.

For externally captured v12 raw result words, app.classify(words, window_tag=17) validates the complete frame and runs its head through the existing C parser and readout. It rejects truncation, extra words, incorrect tags/metadata, record-count mismatch, duplicates, faults and nonfinite scores. Hashless frames report result_hash_source: host_context; this cannot attest the executed image or session. Bind capture, bit/HWH and session provenance separately. Board.run() returns decoded results, not raw words; pass those through app.run rather than passing its mapping to classify.

Exports require a fresh destination and write manifest.json last. A partial directory is not complete. Model/head/package hashes catch inconsistent assets; they do not authenticate a self-provided manifest. The head loader bounds both compressed and expanded sizes and validates array headers before allocation. Retain trusted release hashes independently. Replace an application by exporting to a new directory and explicitly loading it; keep the old directory for rollback.
