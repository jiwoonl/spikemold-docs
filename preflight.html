Check a model before training#

Run a complete CPU example from the repository root after installing the compiler extra. Choose a new directory:

python examples/compile_model.py --output /tmp/spikepress-preflight-new
python -m json.tool /tmp/spikepress-preflight-new/preflight.json
python -m json.tool /tmp/spikepress-preflight-new/compiler_report.json
spikepress inspect /tmp/spikepress-preflight-new/model.spm

preflight.json contains advisory inspection; the compiler report records exact acceptance for this model, shape and target. preparation.json records the preparation step and validation.json records the example’s host golden check. No board is accessed. To select a real deployment image’s profile on the workstation, supply --bitstream bitstreams/pynq-z2/spikemold.bit with its matching HWH and profile sidecar. The image must already be available and qualified; reading it does not program a board.

For your own model, run a static target check before investing in training:

import runpy
import spikepress

model, example = runpy.run_path("examples/compile_model.py")["make_model"]()
report = spikepress.preflight(model, example)
print(spikepress.format_preflight(report))

For image-bound inspection, pass bitstream="bitstreams/pynq-z2/spikemold.bit" to preflight and the compiler for that same bundle. With no bundle this remains a software-contract exercise, not hardware admission.

In the native event path, rejections identify known target incompatibilities, including intermediate AvgPool, biased neural operators, excessive residual merges and unqualified geometry. warnings identify host work or virtual boundaries that add latency, traffic and STARTs. unknowns identify what static module inspection cannot prove, such as functional operators or execution order in an opaque model. An empty rejection list does not guarantee compilation success.

Pass compilation=spikepress.check(prepared.eval(), example, target=...) to the formatter with a preflight report for the same model and target to display actual compiler acceptance or rejection. Checkpoint-time reports and periodic training metrics can share TrainingMonitor; see the training workflow and runnable example.

Spatial Flatten can require an exact virtual PS bridge. A known 1x1 spatial Flatten is a no-op and does not receive that overhead warning. A terminal GAP/Linear head, with or without bias, must be split explicitly into a compiled backbone and a host classifier. Intermediate AvgPool is unsupported in that native path; explicit supported C host capture is a separate option. Placing it on the PS does not automatically make its multi-bit output a valid binary event input for the next FPGA layer.

prepare() includes the report in its return value. Public PYNQ-Z2 compilation emits boundary warnings once for the outer call; its existing validation and errors remain authoritative. The training entrypoints inspect the model before calibration and optimizer updates and record the report in their run metadata. They can still train an off-target research model after warning; that does not make the resulting checkpoint deployable.

See host classification and recipe limits for the supported split and qualification boundaries.

Reading status messages#

Message

What to do

CANDIDATE_REQUIRES_COMPILE

Existing tiling/partitioning may fit. Check the actual model and shape.

CANDIDATE_REQUIRES_RETRAIN_AND_COMPILE

Change the architecture/weights explicitly, retrain or fine-tune and validate.

Compiler: NOT_SUPPLIED

No separate compiler result was supplied to the formatter. A size estimate does not prove fit.

Compiler: NOT_RUN

Validation was explicitly skipped; compile before deployment.

Compiler: ACCEPTED

The supplied compiler report accepted that example and parameters. Board qualification remains separate.

Compiler: REJECTED

The current model fails the current compiler contract. Follow its node/code/hint; do not deploy it.
