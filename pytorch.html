Authoring with PyTorch#

SpikePress keeps torch.nn.Module, state_dict, autograd and ordinary optimizers. Its native event layers define the bounded integer neuron behavior that can be compiled. An arbitrary SpikingJelly or snnTorch checkpoint is not automatically equivalent to these layers.

Moving from SpikingJelly or snnTorch#

Familiar workflow

SpikePress behavior

Construct a torch.nn.Module

Compose native layers from spikepress.nn; ordinary torch.nn host operators require explicit supported hybrid compilation.

Select single-step or multi-step mode

Pass the full B,T,C,H,W or B,T,C,L tensor to native event layers and set SparseEventTrainingPreset(timesteps=T). T is 1–64.

Carry membrane state across calls

Native event state resets between forward calls and carries only within T. Do not assume a library’s persistent-state behavior.

Reset neuron state at a sequence boundary

Each native forward call is already a new sequence. There is no general external-library reset adapter.

Use an optimizer and surrogate gradients

Native layers expose trainable parameters and their documented QAT/surrogate semantics. Training dtype does not imply floating-point PL execution.

Load a pretrained state_dict

Reconstruct the matching architecture, configuration and numeric meaning first. Matching tensor shapes alone do not prove equivalence.

Export after model.eval()

prepare creates a deployment copy; compile decides exact acceptance. It does not silently replace unsupported operators.

See training for a complete optimizer loop and layer reference for constructor signatures. Binary event tensors represent spikes, not arbitrary analog features. Explicit direct-current and hybrid paths have separate contracts.

A complete classifier optimizer loop#

The following CPU example defines its model, data, labels, loss and optimizer. It performs two updates on synthetic binary windows. The terminal host head uses the same temporal/spatial mean as the deployed mean head. It demonstrates API integration, not learned dataset accuracy.

import torch
import spikepress
from spikepress.nn import IFLinear
from spikepress.sparse_event_training import SparseEventTrainingPreset

torch.manual_seed(7)
backbone = torch.nn.Sequential(IFLinear(
    8, 8, preset=SparseEventTrainingPreset(timesteps=4)))
head = torch.nn.Linear(8, 2)
inputs = (torch.rand(2,4,8,1,1) > 0.5).float()
labels = torch.tensor([0,1], dtype=torch.long)
optimizer = torch.optim.SGD([*backbone.parameters(), *head.parameters()], lr=0.01)
for step in range(2):
    optimizer.zero_grad(set_to_none=True)
    features = backbone(inputs).mean(dim=(1,3,4))  # B,C
    logits = head(features)
    loss = torch.nn.functional.cross_entropy(logits, labels)
    assert torch.isfinite(loss)
    loss.backward()
    optimizer.step()

# Export only the supported backbone; the biased head is a host component.
prepared, details = spikepress.prepare(backbone.eval(), inputs[:1], validate=False)
compiled = spikepress.compile(prepared, inputs[:1])
assert compiled.rejection_report["accepted"]
print("PyTorch classifier update and backbone export: PASS")

PyTorch classifier update and backbone export: PASS

For deployment, pass your matching bitstream= to preparation and compilation, then bind head.weight.detach().numpy(), head.bias.detach().numpy() and the class order with application export. Keep the trained head in your checkpoint as well as the backbone. In a real task, use a DataLoader and an independent validation split; see data preparation. The fully saved/resumable CPU workflow is described in runnable examples.

Precision, performance and checkpoints#

Native deployment uses signed INT4 weights and INT16 state with defined accumulation, saturation, reset and decay. Floating-point shadows enable training; prepare is not a general post-training converter. The supported retention codebook is 1, 1/2, 1/4, 1/8 and 1/16 where admitted. Continuous PLIF or subtractive reset can have different semantics; explicit approximation needs error bounds and task-accuracy validation. Hybrid C paths follow source float32/float64 by default; dynamic INT8 is explicit and requires validation. See parameters and operations.

Native state carries within a full temporal forward and resets between calls. Optional CPU and CUDA multi-step paths have different limits; inspect the observed execution report and benchmark after warmup. See training and execution.

Save architecture, T, reset/decay, precision and execution configuration with state_dict, and optimizer/RNG/loader state for your own resumption contract. prepare deep-copies and preserves train/eval mode; an optimizer for the original does not update the copy. Prepare an evaluation model, recompile after changes, and keep deployment .spm files separate from checkpoints. The synthetic example’s tested resumption covers CPU step boundaries, not arbitrary distributed training.
