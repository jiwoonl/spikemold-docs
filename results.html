Performance#

These are measured application results on PYNQ-Z2. They cover the complete ARM host + FPGA API path, including the selected native C classifier. They are not FPGA-only kernel benchmarks or measurements on arbitrary new inputs. Model, input, checkpoint and protocol hashes are retained in the machine-readable results.

Measurement conditions#

Setting

15-model campaign

Board / accelerator clock

PYNQ-Z2 / 100 MHz

Batch

One input window per call

Input

One stored input per model, repeated for timing

Warmup / samples

Two warmups, ten serial timed calls per path

Wait policy

Latency-oriented polling

Ordinary call

Input packing, transfer, FPGA execution, completion and host head

Prepared call

Same fresh transfer/execution/head; first packing/seal is outside the timed call

Excluded setup

Model loading, first preparation, file capture and golden comparison

Accuracy column

Software validation of the selected checkpoint; not full-dataset FPGA accuracy

The source snapshot for this campaign is 739e1eca. Later packaging and documentation changes do not create new physical measurements. The included image retains the same verified image bytes.

Same-model comparison#

A separate historical DVS checkpoint was measured with its previous implementation and the included deployment image. Both used the same checkpoint, float32 input, head, batch 1, T16, 100 MHz PL, 650 MHz ARM and auto wait policy. Latency uses 12 calls; throughput uses a separate continuous 20 calls. Current ordinary inference was repeated after restoring the included image.

Verification and limitations#

All 30 original model/path runs passed. Independent replay checked 350 captured frames and 300 timed outputs. The matched comparison passed 12 full output tensors and 128 timed feature/logit outputs. The included image was restored to 100 MHz and idle. Its observer remains inference_only with measurement_valid=false. Gesture LIF32 exceeds the qualified four-tile bound; other unsupported/unexported models retain their compiler and provenance blockers.

Evidence and reproduction#

Raw inputs, outputs, scripts and source manifests are retained in the 24,492,092-byte review archive, SHA-256 68672474d15bbfe46613cbc183347081fd915c7de210639e46b849d61cdb5eda. The archive includes 1,385 payloads and passed fresh-extraction checks. The legacy runtime capture contains the executable-code/native subset and its original full-kit manifest. Full training data, large checkpoints and the complete historical kit are external. Evidence and retrieval

The full trained checkpoints, datasets and historical runtime kit are not the small examples shipped with this SDK. Use the runnable example catalog for a self-contained CPU workflow and the board walkthrough for first execution with the included image. Replicating a performance row requires its exact external model/input/head/protocol assets. CPU recurrence and host INT8 microbenchmarks have their own conditions in execution; they do not establish full-model or FPGA speedup.
