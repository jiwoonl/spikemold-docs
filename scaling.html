Training and deployment at the selected hardware scale#

Run preflight with the intended input before the first compile or epoch. For native Sequential backbones, static shape/budget inspection does not execute or copy the model. Model-provided graph metadata and the explicit merge + CountReadout dialect use isolated copies; capture can materialize the compiler and consume additional device memory. CPU RNG is restored. CUDA RNG and arbitrary external Python side effects are outside that guarantee. For a temporal image model, supply the real B,T,C,H,W geometry rather than one frame. Persist the returned JSON and the selected target with the run.

import json
from pathlib import Path
import spikepress

# backbone and probe are the caller's model and representative BTCHW tensor.
bitstream = "bitstreams/pynq-z2/spikemold.bit"
report = spikepress.preflight(backbone, probe, bitstream=bitstream)
Path("preflight.json").write_text(json.dumps(report, indent=2) + "\n")

spikepress.model_preflight.v1 gains an additive hardware_budget field. REJECT identifies an explicit unsupported contract; WARN identifies risks or conditional work. Inspect unknowns and shape_coverage even if no rejection is present. COMPLETE means every inventoried convolution has a static output shape estimate. It does not establish graph placement, mapped FPGA resources, quantized occupancy, or deployment. Unknown convolution geometry is listed in unestimated_nodes and makes coverage PARTIAL; later shapes are never guessed past unsupported operators. Compilation remains authoritative.

The report reads the existing target definitions. It lists row count, dense OC8 entry upper bound, full-state vectors, target limits and conditional options. For the compact target, stage state is limited to 8192 vectors, with four physical stages and up to six logical contexts per stage. These are compiler limits, not a statement that a bitstream meets timing.

An entry upper bound is not measured sparsity. Entry pruning cannot repair row address or spatial-state overflow. If even one OC8 group exceeds full-state capacity, channel pruning alone cannot fit it. No option silently edits the model or guarantees that the compiler will admit it.

spikepress.collect_oc8_statistics(model, loader, maximum_batches=...) accepts binary BCHW and BTCHW events. Temporal calibration counts all B*T*H*W observations per channel and agrees with flattened-frame calibration. Use training/calibration data under the experiment protocol, without opening a holdout to choose masks. Existing sparsify and apply_oc8_sparsity remain the mask/application path; collecting statistics does not modify weights.

Explicit compact export#

For an already hardware-aligned native model, the public path supports the existing compact target explicitly:

import copy

backbone = copy.deepcopy(backbone).eval()
prepared, preparation = spikepress.prepare(backbone, probe, bitstream=bitstream, validate=False)
compiled = spikepress.compile(prepared, probe, bitstream=bitstream)
path = spikepress.save(compiled, "backbone-compact.spm")
package = spikepress.load(path)

Preparation reports compiler compatibility as NOT_RUN in this example; use compiled.rejection_report for the result of the one explicit compile.

The default pynq-z2 target stays unchanged. Existing public-v1 artifacts keep their format and validator. Compact save/load dispatches to the existing compact validator using the declared target; it does not convert, relabel or reseal a package. Target/schema/source-identity mismatches are rejected before creating the file. Existing destination files are protected by default. Ordinary compact virtual-segment bridging remains unsupported.

To transition an existing public-v1 export, recompile the original supported model/checkpoint with the explicit compact target, compare integer golden and readout outputs, and save a new artifact. Editing the old manifest is invalid. Runtime loading selects the compact runner, but successful mock input preparation does not prove transport, RTL execution, board timing or hardware inference.

Multi-step training cost#

The existing implementation already batches convolution over B*T. Its optional CUDA compile_multistep path remains available. Saturation-sensitive integer accumulation retains its canonical fallback; reset, decay, surrogate gradients and temporal state must keep their existing order.

An opt-in optimization skips unused activity telemetry:

# Only when this layer's activity metrics/regularizers/hooks are unused.
event_layer.collect_activity = False

The default is True, including legacy instances without that attribute. With collection disabled, final membrane fields remain available, and telemetry contains activity_collected=False. Entropy, extra work convolution and other activity statistics are omitted. The sparse-event regularizer rejects missing activity explicitly. Keep collection enabled for training that uses work/tap regularization, activity metrics, model selection or telemetry hooks. Agent3’s native training caller uses these metrics and keeps the default.

Regression checks cover exact outputs, input/weight/threshold/decay gradients, SGD update, masks/grouped/parametrized weights, integer export and actual saturating fallback. This flag changes telemetry cost; it does not change the logical batch, microbatch accumulation, optimizer or training protocol.

Fixed CPU evidence#

Evidence is under build/agent2-sw-framework/a2-w007-hw-scale/. Issue #15 owns live coordination; this document describes the software behavior and evidence boundaries, without mirroring peer progress.

The unchanged trained lif_dvs checkpoint has SHA256 8354d9096c3ce35bd48aa4626f9cde3b776ab81de9e64ff129d0bba7d7b32c6e: T16, binary 2x128x128, five width16 Conv/Pool blocks and a separate PS float head. Its compact package has ten lowered layers in three stages with state 8192/8192/3360. The early report warns that the first layer’s un-tiled full state needs 32768 vectors, and offers the existing tiling path. Successful compilation demonstrates why a warning is not an unconditional rejection.

The compiler now skips exhaustive P25 segmentation when an individual layer’s full state already exceeds stage capacity, then uses the existing P26 spatial fallback. Layers at or below capacity retain P25. For this real checkpoint, schedule calls fall from 139 to 29. One ordered shared-host cProfile trial measured 87.682s before and 80.376s after; this is not a stable throughput claim. Canonical package JSON is byte-identical (SHA256 fa652db9f64e3f35902fe19b457e00e492a20f06e7814b664883e29e47bffcbd) and all 2449 golden spikes match. Public save/load and mock runtime preparation produce the same 66626 input words. The saved artifact SHA256 is 0a7eb5afd6eae0bb1e0feaa0d6f0ff72a16339cf7605f2e0691c7e00c01f633c.

Agent3’s native entrypoint writes hardware-preflight.json and its stderr diagnostic before the first authoritative compile. The hook keeps the existing pynq-z2 target and binds preflight.py in run provenance. Its source SHA256 is cdd27d6868c4d23fa20728ef27e6b2296edfc9c446e8434dadfd31741dad23a5; the paired report-v3 SHA256 is 58d19a9fcf64a2c026341a02d1ae8508e28174bdb033dd3df50a40ebb0200fa2. Producer and independent consumer each pass three tiny CPU checks covering report-before-compile rejection, model/mode/RNG preservation and exact forward/gradient/AdamW state/INT4-code behavior. The entrypoint is Agent3-owned; these exact source bytes are copied in peer-hook-consumption-r2/source/ for review, rather than overwriting this checkout’s older examples.

The independent compact intake verifies Agent3’s 177 source files and 11 model assets, copies its repaired export and acceptance/result/thermal receipts, and checks artifact bytes, package and golden against Agent2’s independent result. peer-compact-consumption/ and peer-compact-runtime/ bind that handoff to current load/mock-input behavior. No costly model compile was repeated solely to join metadata or acknowledge unchanged bytes.

For one CPU layer, forward+backward at two threads and BTCHW [2,8,8,32,32], 12 alternating pairs measured median 6.459ms with activity versus 5.552ms without (about 14% less time). Raw paired samples, environment and benchmark source are retained in training-worker/. This does not measure GPU or whole-model training speed. No training campaign, board run, release build, FPGA throughput, mapped timing or electrical-energy result was produced.

Compiler optimization of PL execution#

The implementation sequence is legal schedule selection, source-bound activity calibration, weight layout alignment, tile geometry, then model-changing structured pruning. Static validation specialization is a separate joint compiler/runtime/RTL task. Issue #15 owns progress and peer decisions; the following gates define the work, not an assertion that every optimization is implemented or qualified on hardware.

Workstream

Existing path and proposed change

Acceptance and stop condition

Legal schedule selection

Extend the P26 planner’s ranking of already validated candidates; first minimize physical passes, then ordinary cut-stream word bounds, then stage count. Reuse P25 residency DP.

Same model/numerics, no extra passes, reduced cut bound on a reproducible fixture; unchanged tile replay and passing package, golden and runtime checks. Stop on state/residual/readout mismatch or no cost improvement.

Activity-aware ranking

Reuse the cost-model calibration and admission patterns with a compact/P25/P26-specific calibration, graph/source hashes and fixed representative inputs. Keep worst-case capacity checks.

Validate estimates against held-out calibration inputs from the approved calibration pool and source-matched PL cycles. Preserve the static fallback for missing/out-of-range calibration. Do not reuse temporal4 coefficients for an unqualified target or choose plans using official test data.

Regular weight alignment

Investigate naturally aligned legal stage partitions first. A padding policy requires an explicitly versioned producer/loader contract.

Exact CSR, parameter order, thresholds, outputs and capacity including padding; old-layout packages retain their original admission. Reject unbound gaps, ambiguous revisions and malformed tails. Require Agent1 agreement and source-matched loader/fast-path proof before adoption.

Tile/halo reuse

Reuse P26’s explicit row bands within current 2–4-tile, power-of-two row-count and state-capacity constraints.

Every output row covered exactly once, halo and state/spikes exact at every timestep, legal first/last and publication lifetime. Stop if a proposed band needs validator relaxation, more passes without a justified benefit, or unsupported tile count.

Structured pruning/substitution

Reuse training-calibrated OC8 statistics/masks; change widths only through an explicit model rewrite that updates all consumers, concat/residual paths and the PS head.

Demonstrate reduced actual packed work/state, fine-tune and evaluate under Agent3’s frozen accuracy protocol, then export/compile/golden again. Stop if only CSR sparsity improves while the deployed dense block remains unchanged, or accuracy/support gates fail. No automatic operator replacement.

Static validation specialization

Reuse existing static admission/certificates; connect the checked bytes to the actual DMA buffers, publication generation, ownership and last read.

Producer and runtime must agree on an immutable-byte/lifetime proof and fault/CLEAR recovery. Keep dynamic bounds, ownership, fault, drain and backpressure guards. A deepcopy or digest alone is insufficient; no additional guard removal is justified without this proof.

P26 schedule ranking uses a worst-case logical stream-word bound, not a cycle model. The tile geometry is fixed for a graph and is not changed by this ranking. Arena allocation size includes padding and reserved capacity; it must not be presented as bytes actually transferred. Any cost that does not vary between candidates must not be counted as a new reduction. A change in stage boundaries can alter image loading or execution overhead even with the same pass count; source-matched RTL measurements are required to establish a speedup.

The current tile planner rounds resident rows down to a power of two because the P26 validator requires power-of-two row counts, and the RTL loader uses the first band’s shift to check state capacity. Replacing this with the raw maximum row count is not a legal optimization under the current contract. Eight tiles also require joined count/index, descriptor RAM, input-table and lifetime changes; increasing a Python limit cannot establish support. Splitting a non-power-of-two tail into additional legal tiles may improve admission but is not, by itself, a performance optimization.

Generic GPX1 weight payloads use dense blocks even when their source CSR omits zero groups. The existing exact diagonal layout is already specialized. Unstructured or OC8 mask pruning therefore does not guarantee fewer PL issues or reads. Channel permutation also needs consistent adjacent weights, neuron parameters, state and readout indexing; mixed-sign saturation prohibits an unproved change in accumulation order. Empty input rows or timesteps do not authorize skipping decay, threshold, reset or completion behavior.

Compatibility and measurement#

No new compile option is needed for the legal schedule ranking: normal spikepress.compile(...) uses it when the P26 fallback applies, including an explicit compact target. Explicit stage groups remain a caller constraint. Existing saved packages retain their original schedule and validator; loading does not optimize or rewrite them. Recompilation may produce different stage boundaries and package hashes. Save the new package separately and qualify those exact bytes before replacing a deployed artifact. Reverting the compiler or loading the retained old package restores the old schedule.

For each comparison, bind checkpoint/export, input transform and IDs, target, compiler/package, golden, RTL/filelist and runtime revisions. First compare complete integer outputs and per-timestep state where available; keep PS float head tolerances separately declared. Then compare physical pass count, actual intermediate word traffic, replay words and whole-frame PL cycles. Report host/input/head costs separately and use routed clock measurements for device throughput. A static bound, host replay, mock runtime or one healthy simulated input does not establish board performance, whole-set accuracy or energy.
