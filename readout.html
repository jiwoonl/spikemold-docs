Terminal host classification#

spikepress.readout.linear applies a floating-point classifier on the host to terminal spike records. The accelerator computes the backbone. The host validates record addresses, groups, padded lanes, timesteps and duplicates, reconstructs terminal channels, and averages over time and spatial positions:

features[c] = sum_t,y,x spikes[t,c,y,x] / (T*H*W)

The classifier then applies logits = weight @ features + bias once. It is equivalent to spatial AdaptiveAvgPool2d(1), averaging timesteps, and an ordinary Linear head, including bias. This does not fold a biased classifier into the hardware neuron dynamics. Inside a native resident event graph, Conv/Linear bias and intermediate AvgPool remain unsupported. Explicit supported C host islands have their own precision/domain contract; see execution.

from spikepress import readout

# Use the final layer descriptor of the compiled backbone.
logits = readout.linear(
    result, weight=head_weight, bias=head_bias,
    timesteps=64, output_shape_hwc=(8, 8, 64),
    state_base=final_layer["state_base"],
    state_limit=final_layer["state_limit"],
)
prediction = int(logits.argmax())

Weight shape is classes-by-channels, and bias is one value per class. Both must be finite numeric arrays. Silent channels remain present with zero features. readout.global_average exposes the features without a classifier. The helpers use NumPy and do not require PyTorch on the board. Weights/bias belong to the caller; .spm does not silently contain or run a host head.

Compile the bias-free backbone separately from the host head. Automatic lowering of arbitrary terminal PyTorch heads is not claimed. Training a hybrid classifier must use the same averaging semantics as deployment. A classifier trained on spike counts cannot be reused on rates without adjusting its weight scale.

Report the result as PL backbone + host classifier. Include head runtime in end-to-end latency and energy; do not call backbone-only timing full-model FPGA inference. Software integer spike equality and floating-point host-head reference tests do not establish board execution or task accuracy.

Runnable application example#

From a source checkout with the compiler extra and the native C extension:

python examples/application_deployment.py --output /tmp/spikepress-head-new
spikepress inspect-deployment /tmp/spikepress-head-new/application

The deterministic CPU example exports a mean host head and labels, records the raw and encoded input, and prints an application report. It does not connect to a board or establish accuracy. Use --bitstream bitstreams/pynq-z2/spikemold.bit with a qualified local image and matching HWH/profile files to select a deployment profile. See application deployment for the board lifecycle and preprocessing requirements.
