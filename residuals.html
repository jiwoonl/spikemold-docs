Residual addition#

Residual ADD is supported through an explicit export path. The host retains and concatenates binary intermediate results; existing FPGA synapses consume the expanded inputs. This is host-composed execution, not a resident ADD instruction or a generic conversion of any training residual block.

ADD preserves multiplicity: two coincident spikes produce 2. OR produces 1. Replacing one with the other changes the model. Resident OR is disabled on the included image. Its older OrResidual API remains for compatibility and other admitted profiles; it is not the recommended residual path here.

Run the integer export example#

python examples/residual_add.py --output runs/residual-add

Expected: PASS_CPU_RESIDUAL_ADD, counts [[1, 0]] and hardware: NOT_CHECKED. The example uses the included image metadata and writes model.spm, events.npy, golden_counts.npy and validation.json. It verifies the model, compiler golden and artifact round trip on CPU. The golden is a count vector, not a dense spike tensor.

class ResidualAdd(torch.nn.Module):
    def __init__(self):
        super().__init__()
        self.stem = EventConv2D(8, 8, 1)
        self.stem_spike = LIF(1)
        self.branch = EventConv2D(8, 8, 1)
        self.branch_spike = LIF(1)
        self.add = SpikeAdd()
        self.head = EventLinear(8, 2)
        self.head_spike = LIF(2)
        self.readout = CountReadout()
        with torch.no_grad():
            for layer in (self.stem, self.branch, self.head):
                layer.weight.zero_()
                for channel in range(layer.weight.shape[0]):
                    if layer.weight.ndim == 4:
                        layer.weight[channel, channel, 0, 0] = 1
                    else:
                        layer.weight[channel, channel] = 1

    def forward(self, inputs):
        skip = self.stem_spike(self.stem(inputs))
        branch = self.branch_spike(self.branch(skip))
        return self.readout(self.head_spike(self.head(self.add(branch, skip))))

The model uses the existing integer export markers. Its LIF has fixed quarter retention, INT16 saturation and reset-to-zero. These markers are not the trainable fused spikepress.nn layers; do not mix the two representations or treat this example as surrogate-gradient training.

Using the model and example input defined in the runnable script:

program = spikepress.compile_residual_add(
    model.eval(), example,
    bitstream="bitstreams/pynq-z2/spikemold.bit",
)
spikepress.save(program, "new-residual-model.spm")

Limits#

The graph must satisfy the existing integer, topology, count-domain, no-overflow and capacity checks. Multiplicity is bounded; unsupported raw-input shortcuts, merge patterns and saturation-order changes reject. The compiler does not silently replace ADD with OR or discard branches.

Compile and golden agreement apply to the supplied model/input. Running its program needs the matching board runtime; each call recomputes host-composed intermediates. Generic run_board.py --golden handles a different resident dense-output path and is not this program’s count-output validator. Existing board results for ADD models retain their original source/input scope in performance.
